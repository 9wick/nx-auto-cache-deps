# nx-auto-cache-deps

Automatic file inputs for Nx task caching.

Instead of maintaining file globs in `inputs`, let each task discover its inputs as it runs. `nx-auto-cache-deps` traces file access across the task and its child processes using [fspy](https://github.com/voidzero-dev/vite-task). Changing a file the task read invalidates its cache; editing an unrelated file does not.

Nx continues to store and restore the task's outputs and logs.

Requires **Nx 24** and **Node.js 24 or later**.

## Get started

```sh
nx add nx-auto-cache-deps
```

Installation registers the plugin in `nx.json`. Then enable tracing for the tasks you want to cache.

For a target defined in `project.json`, change its `executor` to `nx-auto-cache-deps:run` and put the previous executor in `original_executor`. Keep its existing options, outputs and dependencies:

```json
{
  "targets": {
    "build": {
      "executor": "nx-auto-cache-deps:run",
      "original_executor": "@nx/js:tsc",
      "cache": true,
      "outputs": ["{options.outputPath}"],
      "options": {
        "outputPath": "dist/libs/a",
        "tsConfig": "libs/a/tsconfig.lib.json"
      }
    }
  }
}
```

Run the task as usual:

```sh
nx run a:build
```

The initial runs discover inputs and populate Nx's cache. Cache restoration can start on the third run. Tasks that discover additional inputs on later runs need more executions before the dependency list stabilizes.

## Tasks inferred by plugins

For tasks generated by an inference plugin, wrap its existing registration in `nx.json` and select the target names to trace. For example, with `@nx/vite/plugin`:

```json
{
  "plugins": [
    "nx-auto-cache-deps",
    {
      "plugin": "nx-auto-cache-deps",
      "options": {
        "wrap": {
          "plugin": "@nx/vite/plugin",
          "options": { "buildTargetName": "build" }
        },
        "targets": ["build"]
      }
    }
  ]
}
```

The wrapped plugin still infers the tasks. Only the selected targets use tracing; other targets, such as `serve`, keep their original configuration. Add one wrapper per inference plugin.

## Environment variables and other inputs

Tracing discovers file inputs inside the workspace. Keep environment variables, external dependencies and runtime inputs declared through Nx.

For explicit executor targets, omitting `inputs` lets the plugin configure file inputs automatically. If you set `inputs` yourself, include `autoCacheDeps-<target>` alongside your other inputs:

```json
{
  "build": {
    "inputs": ["autoCacheDeps-build", { "env": "NODE_ENV" }]
  }
}
```

Wrapped inference targets preserve existing non-file inputs and replace file inputs with the observed dependencies.

## Cache behavior

The plugin tracks file reads, directory listings and probes of missing files. This detects changed or deleted inputs, newly added files in listed directories, and optional files that appear later.

Files outside the workspace, files written by the task, declared outputs, and Nx/Git metadata are excluded. Keep `outputs` configured so Nx can restore the artifacts.

Dependency lists share Nx's cache directory and work across git worktrees. `nx reset` clears them together with Nx's cache.

[How dependency tracking and caching work](https://github.com/9wick/nx-auto-cache-deps/blob/main/doc/caching.md)

## Supported platforms

Tracer binaries are included in the package; users do not need Rust installed.

- Linux: x64 with glibc or musl; arm64 with glibc
- macOS: x64 and arm64
- Windows: x64

Other platforms fail when a traced task executes.

## Remove the plugin

Restore explicit targets' original executors and remove `original_executor`. Move wrapped inference plugins back to their original registrations. Then remove the `nx-auto-cache-deps` registrations from `nx.json` and uninstall the package.
