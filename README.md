# nx-auto-cache-deps

`nx-auto-cache-deps` is an Nx plugin that traces the files a task actually accessed during execution (via fspy) and uses them as the task's cache inputs. You no longer need to maintain file globs in `inputs` by hand or suffer unnecessary cache misses from overly broad globs. Outputs are still cached and restored by Nx's own cache, and dependency lists are shared across git worktrees just like Nx's cache.

## How It Works

### Two-Stage Cache

The plugin uses two layers of caching:

| Cache | Key | Value | Managed By |
| --- | --- | --- | --- |
| **Dependency List** | Task (`<project root>:<target>`) | Set of observed file access queries | `nx-auto-cache-deps` |
| **Execution Result** | Nx task hash (includes dependency list hash) | Artifact outputs and logs | Nx |

1. When Nx computes a task hash, `nx-auto-cache-deps` looks for an existing dependency list for the task.
2. **If no dependency list exists**: The plugin returns a different value each time. This guarantees a cache miss in Nx, forcing the command to run.
3. **If a dependency list exists**: The plugin evaluates the recorded dependencies against the current filesystem and returns their hash. Nx includes this hash in the task hash and queries its cache, restoring existing outputs on a cache hit.
4. When the command executes, fspy traces the process tree. Upon successful completion, the observed dependencies are saved to the dependency list.

> **Note on Initial Cache Hits**: The result of a run executed without a dependency list is saved under a key that does not include dependency hashes and is not reused. The subsequent run computes a hash from the newly saved dependency list, executes, and caches its outputs under that hash. The first cache restore can occur on the **3rd run**. If later runs discover additional dependencies (for example, Windows shell commands can list additional directories once outputs exist), the dependency list expands and another execution is needed to cache results under the updated hash. Cache restoration starts once that list stabilizes.

### What Is Tracked

The tracer monitors the entire process tree (including child processes and native tools) using fspy:

- **File reads**: Detects content modifications, deletions, or replacement by directories.
- **Directory listings**: Detects additions, deletions, renames, or type changes of entries within listed directories (allowing detection of newly added files matching glob searches).
- **Probes of missing paths**: Detects when previously non-existent paths are created.

### What Is Excluded

The following paths are excluded when recording dependencies:

- **Paths outside the workspace**: System files, Node.js binary, etc., are ignored.
- **Paths written by the task**: Prevents generated outputs from being treated as task inputs.
- **Target `outputs` and parent directories**: Output artifact paths and parent directory probes are not recorded, and directory listings ignore entries leading to outputs. Artifacts are restored by Nx, so removing them is not treated as an input change.
- **Nx and Git metadata**: `.nx/` and `.git` are excluded (matching Nx's own task hashing behavior).

### Worktree Sharing

Dependency lists are saved under `nx-auto-cache-deps/` inside Nx's cache directory (`~/.nx/<id>/cache` in Nx 24). Because paths are stored relative to the workspace root, dependency lists are shared across git worktrees for the same workspace. Running `nx reset` clears the dependency lists along with Nx's cache.

## Installation

```sh
nx add nx-auto-cache-deps
```

This installs the package and runs `nx-auto-cache-deps:init`, which registers `"nx-auto-cache-deps"` in `plugins` in `nx.json`.

## Configuration

There are two ways to configure targets depending on how they are defined:

### 1. Targets Generated by Inference Plugins

For plugins that infer targets from configuration files (such as `@nx/vite/plugin`), wrap the plugin in `nx.json` and specify target names in `targets`:

```json
{
  "plugins": [
    {
      "plugin": "nx-auto-cache-deps",
      "options": {
        "wrap": { "plugin": "@nx/vite/plugin", "options": { "buildTargetName": "build" } },
        "targets": ["build"]
      }
    }
  ]
}
```

- Targets not listed in `targets` (e.g. `serve`) continue to use inferred configuration as-is.
- Add one `nx-auto-cache-deps` registration per wrapped plugin.
- File-based inputs in `inputs` are replaced by the dependency list hash, while non-file inputs (environment variables, external dependencies, runtime inputs) and existing target settings (`options`, `outputs`, `dependsOn`, `cache`) are preserved.

### 2. Targets with Explicit Executors in `project.json`

For targets with an explicit executor in `project.json`, set `executor` to `nx-auto-cache-deps:run` and specify the original executor in `original_executor`:

```json
{
  "targets": {
    "build": {
      "executor": "nx-auto-cache-deps:run",
      "original_executor": "@nx/js:tsc",
      "cache": true,
      "outputs": ["{options.outputPath}"],
      "options": { "outputPath": "dist/libs/a", "tsConfig": "libs/a/tsconfig.lib.json" }
    }
  }
}
```

These targets are handled by the top-level `"nx-auto-cache-deps"` plugin registered by `nx add`.

#### Combining with Environment Variables and Other Inputs

The plugin provides a named input formatted as `autoCacheDeps-<target>` (e.g. `autoCacheDeps-build`).

- If `inputs` is omitted in `project.json`, the plugin automatically sets `inputs` to `["autoCacheDeps-<target>"]`.
- If you define `inputs` explicitly (for example, to include environment variables), include `autoCacheDeps-<target>` alongside them:

```json
{
  "build": {
    "executor": "nx-auto-cache-deps:run",
    "original_executor": "@nx/js:tsc",
    "inputs": ["autoCacheDeps-build", { "env": "NODE_ENV" }]
  }
}
```

## Supported Environments

Tracer binaries are bundled for all supported platforms:

| Item | Supported |
| --- | --- |
| OS & Architecture | Linux x64 (glibc / musl), Linux arm64 (glibc), macOS x64 / arm64, Windows x64 |
| Nx | 24 |
| Node.js | >= 24 |

Running on other environments will fail with an error when executing target tasks.

## Uninstall

- **Wrapped inference plugins**: Move the plugin configuration in `nx.json` back to top-level `plugins` and remove the `nx-auto-cache-deps` wrapper.
- **Explicit executor targets**: In `project.json`, restore `executor` to the value of `original_executor` and remove `original_executor`.
- Remove `"nx-auto-cache-deps"` from `nx.json` plugins and remove the package from `package.json`.
