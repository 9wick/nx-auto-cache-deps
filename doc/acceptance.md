# 受け入れ条件

実際の Nx・fspy・ファイルシステムを使う統合テスト (`test/`) で確かめる。
`nx add` はパッケージのインストールと `<パッケージ>:init` の実行を行う。A12 はインストール済みの状態で `init` を実行して確かめる。
各行は「事前状態 → 操作 → 期待結果」。

| ID | 条件 |
| --- | --- |
| A1 | 依存一覧なし → 実行 → コマンドが動き、依存一覧が保存される |
| A2 | 依存一覧なし → 2回続けて実行 → 2回ともコマンドが動く（一覧なしの結果は再利用しない） |
| A3 | 同じ依存一覧のキーで保存済み・前回と同じ入力 → 実行 → コマンドは動かず、Nx が成果物を復元する。成果物とその親ディレクトリを消していても同じ。実行で新しい依存が見つかった場合は、拡張した一覧のキーで結果を保存する実行が必要 |
| A4 | 読んだファイルを編集 → 実行 → コマンドが動く |
| A5 | 読んでいないファイルを編集 → 実行 → コマンドは動かない |
| A6 | 列挙したディレクトリにファイルを追加 → 実行 → コマンドが動く |
| A7 | 存在しなかったファイルを作成 → 実行 → コマンドが動く |
| A8 | コマンドが失敗 → 依存一覧は更新されない |
| A9 | 推論プラグインを `wrap` で包む → `targets` の target だけが組み替わり、元の `options`・`outputs`・`dependsOn` が残る |
| A10 | `project.json` で `executor` を差し替える → 元の executor が元の `options` で動く |
| A11 | worktree A で一覧と結果を作る → 同じ入力の worktree B で実行 → コマンドは動かず復元する |
| A12 | `nx add nx-auto-cache-deps` が実行する `init` → `nx.json` に `wrap` なしの登録が1つだけある状態になる。`wrap` 付きの登録しかなければ追加し、再実行しても重複しない |
| A13 | `project.json` で executor を差し替えた target の `inputs` に `autoCacheDeps-<target>` と環境変数を書く → 依存一覧と環境変数が同じなら復元し、どちらかが変われば実行する |
| A14 | 空白・日本語を含むワークスペースと入力ファイル → 同じ入力では復元し、入力変更では実行する。成果物を削除しても復元する |
| C1 | Nx 設定のない workspace で CLI を繰り返す → 成功ログと成果物を復元し、読んでいないファイルの変更では実行しない |
| C2 | CLI が読んだファイルの変更、列挙先への追加、欠落ファイルの出現 → 再実行する |
| C3 | コマンド・引数・作業ディレクトリ・環境変数が異なる → 個別のキャッシュを使う |
| C4 | CLI コマンドが失敗する → 終了コードを保ち、成功キャッシュと依存一覧を置き換えない |
| C5 | CLI コマンドが既存入力を読み書きする → 実行前の内容で判定し、変更後の内容だけを理由に誤ってスキップしない |
| C6 | 同じ CLI コマンドを同時起動する → 一度だけ実行し、もう一方は完成した結果を復元する |
| C7 | 2つの CLI コマンドを `&&` で連結する → 個別にキャッシュし、前半が失敗したら後半を実行しない |
| C8 | ローカル node_modules/.bin のコマンドを渡す → 引数を保って実行・復元する |
| C9 | キャッシュのログ・成果物が壊れている → 再実行で隠さずエラーにし、ログの検査前に workspace を変更しない |
| C10 | 既存ディレクトリにも mkdir する → その下で読んだ入力の変更を検出する |
| C11 | 追跡に記録されない削除を検出 → 警告し、結果はキャッシュしない |
| C12 | 成果物の symlink・実行権限 → キャッシュから復元する。POSIX で入力 symlink のリンク先変更も検出する |
| C13 | POSIX で SIGTERM によって中断 → 子プロセスの書き込みを停止し、次の起動でロックを取得できる |

| E1 | 既定設定 → システム用の変数を受け渡し、独自変数を除く。untracked な値だけの変更では同じ fingerprint |
| E2 | env の一致・否定パターン → 指定した変数だけを受け渡して値を追跡する。値の欠落と空文字列も区別する |
| E3 | env と untrackedEnv に両方一致 → env を優先。設定自体の変更も fingerprint に反映する |
| E4 | JSONC と extends → CLI / Nx runtime / executor で同じ設定を読む。不正・重複設定はエラー |
| E5 | CLI の Nx PID・JOB_ID 等だけ変更 → ヒット。tracked な値変更 → 再実行 |
| E6 | Nx executor で同じ設定 → 受渡しとタスクハッシュの両方に反映。未指定変数は渡らない |
| E7 | Nx run-script から CLI を呼ぶ → Nx の起動ごとの PID で CLI キャッシュを無効にしない |
| E8 | Nx の .env から tracked な値を読み込む → その値を実行とハッシュの両方に使う |
| E9 | Windows の変数名の大文字小文字だけを変更 → 同じ意味で受け渡してハッシュする |

Linux x64 (glibc / musl)、Linux arm64 (glibc)、macOS x64/arm64、Windows x64 で同じ条件を検証する。
