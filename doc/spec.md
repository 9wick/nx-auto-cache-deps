# 仕様

## 目的

タスクが実行時に実際に参照したファイルから、Nx のキャッシュ入力を自動で決める。
利用者が `inputs` のファイル一覧を手で維持しなくてよくし、広い glob による無駄なキャッシュミスを減らす。
成果物の保存・復元、worktree 間の共有は Nx の既存キャッシュに任せる。

## 単独 CLI

`nx-auto-cache-deps <command> [args...]` は、Nx のタスクとは独立したコマンドごとのキャッシュを提供する。
追跡と依存の fingerprint は Nx 版と共通で、ログと成果物の保存・復元は CLI が行う。

- コマンド・引数・作業ディレクトリ・選択した環境変数・実行ファイル・ランタイム・プラットフォームで識別する。環境変数の識別データには値のハッシュを使う。
- workspace 内の読み取り・ディレクトリ列挙・欠落パスの問い合わせを入力として評価する。`.git` と `.nx` は除く。
- fspy が直接記録しない readlink の変更を見落とさないよう、workspace 内の symlink 一覧とリンク先も照合する。成果物の symlink はこの一覧から除く。
- 成功時の stdout / stderr と、追跡で確認した書き込み先を保存する。ヒット時は実行を省略して復元し、終了コード 0 を返す。
- 既存入力を読み書きする場合は、実行前の内容で照合する。初めて見つかった変更入力の実行結果は保存せず、次回の実行で保存する。
- コマンド失敗時は元の終了コードを保ち、依存一覧と成功キャッシュを更新しない。追跡不完全や未記録の filesystem 変更があれば警告し、その結果は保存しない。
- 同じコマンドの照会・実行・保存・復元は OS のファイルロックで直列化する。ファイルを不変のエントリへ保存してから index を atomic rename で更新する。
- 壊れたキャッシュはエラーにする。復元先の親 symlink が workspace の外を指す場合もエラーにする。
- `&&` の制御は呼び出し元の shell が行う。各 CLI は独立して成功・失敗を返す。

標準入力、ネットワーク、時刻、workspace 外のファイルに依存する処理、対話処理はこのキャッシュの対象外とする。
以下の2段階キャッシュと Nx との接続は、Nx プラグイン版についての仕様。

## 共通の環境変数方針

`nx.json` の該当プラグイン登録の `options.env` / `options.untrackedEnv` を CLI と Nx executor が共通で使う。

- `env` の既定は空配列。glob に一致した ambient な変数を渡し、値をハッシュする。
- `untrackedEnv` は Vite Task を基準としたシステム・CI・IDE 用の既定リストへ追加する。一致した変数は渡すが値をハッシュしない。
- `!` の除外は各リスト内で適用する。両リストに一致した変数は `env` を優先する。
- それ以外の ambient な変数は渡さない。色設定が選択されていなければ `FORCE_COLOR=1` を補う。
- Nx の通常の設定読み込み・ハッシュ計算・実行管理に使う親プロセスの環境は変更しない。追跡下で実行する元の executor / コマンドへ渡す環境を選択する。
- fspy 自身の初期化にはホストの環境を使う。選択済みのコマンド環境は権限を制限した一時ファイルで tracer に渡し、実行後に削除する。キャッシュエントリにその一時ファイルを残さない。
- ハッシュには選択方針と tracked な値を含める。値自体をハッシュしない変数も、設定パターンの変更はハッシュへ反映する。
- Nx 版では既存の runtime named input に環境変数の fingerprint を含める。CLI 版ではコマンドの識別キーへ含める。
- Windows の変数名照合とハッシュは大文字小文字に依存させない。
- JSONC と Nx の浅い `extends` を読み、設定は一つのプラグイン登録で定義する。不正な設定や複数の定義は実行前にエラーにする。

0.0.7 の CLI の全変数継承・全値ハッシュからの動作変更になる。既存の利用者も、必要な変数を明示する。

## 2段階キャッシュ

キャッシュを2つ持つ。

| キャッシュ | キー | 値 | 持ち主 |
| --- | --- | --- | --- |
| 依存一覧 | タスク (`project:target`) | 実行時に観測した依存クエリの集合 | 本プラグイン |
| 実行結果 | Nx のタスクハッシュ（依存一覧から計算した値を含む） | 成果物・ログ | Nx |

1. Nx がタスクハッシュを計算するとき、本プラグインは依存一覧を探す。
2. 依存一覧がなければ、毎回異なる値を返す。実行結果のキャッシュには必ずミスし、コマンドを実行する。
3. 依存一覧があれば、その依存を現在のファイルシステムで評価したハッシュを返す。Nx はそれを含むキーで実行結果を照会し、あれば復元する。
4. コマンドを実行するときは追跡し、成功したら観測した依存を依存一覧へ保存する。

依存一覧がない最初の実行の結果は、一覧がない状態のキーで保存されるため再利用されない。
次の実行で一覧から計算したキーの結果が保存され、それ以降の同じ入力で復元される。

## 依存クエリ

| 観測 | 記録するもの | 検出する変化 |
| --- | --- | --- |
| ファイル読み取り | パス | 内容の変更・削除・ディレクトリへの置き換え |
| ディレクトリ列挙 | パス | エントリの追加・削除・改名・種類の変更 |
| 存在しないパスへの問い合わせ | パス | そのパスの出現 |

読み取りと存在の問い合わせは同じ「パスの状態」として評価する。状態は「ファイル（内容ハッシュ）」「ディレクトリ」「存在しない」のいずれか。
glob の探索は、探索で列挙したディレクトリが依存になるので、マッチするファイルの追加を検出できる。
個別の参照先を変える設定ファイルの変更は、その設定ファイル自身の読み取りで検出する。

## 依存一覧の作り方

- 子プロセスやネイティブツールを含め、タスクのプロセス全体を追跡する。追跡は fspy で行う。
- ワークスペース内のパスだけを、ワークスペースルートからの相対パスで記録する。ワークスペース外（Node.js 本体・OS のファイルなど）は記録しない。
- その実行で書き込んだパスは入力から除く。成果物を自分の入力として扱い続けないため。
- target の `outputs` は入力として評価しない。成果物の中のパスと、成果物の親ディレクトリの存在確認は記録せず、ディレクトリ列挙では成果物へ通じるエントリを無視する。成果物は Nx が保存・復元するもので、消しても入力の変化として扱わないため。
- Nx のワークスペースデータ (`.nx/`) と Git のメタデータ (`.git`) は、Nx 自身がタスクハッシュに含めないため除く。
- 依存一覧は保存済みの一覧との和集合にする。configuration や引数の違いで参照するファイルが違っても、どれかの実行で参照したファイルの変更を見逃さないため。
- 実行が失敗した場合、または追跡が不完全だった場合は依存一覧を更新しない。

## 保存場所と worktree 共有

依存一覧は Nx のキャッシュディレクトリ (`@nx/devkit` の `cacheDir`) の下の `nx-auto-cache-deps/` に保存する。
Nx 24 はこのディレクトリをワークスペース ID ごとに `~/.nx/<id>/cache` へ置き、worktree 間で共有する。依存一覧も同じ範囲で共有される。
パスはワークスペースルートからの相対パスなので、worktree の場所が違っても同じ一覧を使える。
`nx reset` でキャッシュとともに消え、次回は依存一覧がない状態から始まる。

## Nx との接続

Nx の公開 API だけを使う。

| 層 | 責務 | 使う仕組み |
| --- | --- | --- |
| target の組み立て | 対象 target の executor を `nx-auto-cache-deps:run` にし、依存一覧のハッシュを named input `autoCacheDeps-<target>` として追加して `inputs` から参照する | プラグインの `createNodes` |
| ハッシュ | 依存一覧を現在の状態で評価する | runtime input |
| 実行と追跡 | 元の executor を fspy の監視下で実行し、依存一覧を保存する | executor `nx-auto-cache-deps:run` |
| 成果物 | 保存・復元 | Nx 標準キャッシュ |

対象 target の選び方は、target の作られ方で2通りある（[利用手順](./usage.md)）。

- 推論プラグインが生成する target: 本プラグインがその推論プラグインを包み、選んだ target を組み替える。推論は毎回元のプラグインが行うので、元の設定の変更に追従する。
- `project.json` で executor を明示する target: 利用者が `executor` を `nx-auto-cache-deps:run` にし、元の executor を `original_executor` に書く。

どちらも、元の target の `options`・`outputs`・`dependsOn`・`cache` はそのまま使う。
`inputs` のうちファイルの指定（named input・glob）は依存一覧で置き換え、環境変数・外部依存・runtime input などファイル以外の指定は残す。
